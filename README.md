# Сайт ресторана «Олива»

Одностраничный адаптивный сайт (ПК / планшет / смартфон), собранный **без единой
зависимости и без сборки**: чистые HTML + CSS + JS. Всё содержимое — тексты, цены,
акции, фотографии, порядок блоков — лежит в одном файле **`data/site.json`**
и меняется без правки HTML.

---

## 1. Быстрый старт

```bash
cd restaurant-site

# вариант А (Node):
node serve.js                 # → http://localhost:8080

# вариант Б (Python, если Node не установлен):
python3 -m http.server 8080   # → http://localhost:8080
```

Откройте `http://localhost:8080`, отредактируйте `data/site.json`, нажмите F5 —
изменения на экране.

> Почему нельзя просто открыть `index.html` двойным кликом: браузер запрещает
> странице читать локальный JSON (`file://`). Через локальный сервер этой
> проблемы нет. Если сервер запустить негде — см. `docs/DEPLOY.md`, раздел 6
> «Если негде запустить локальный сервер».

### Проверки перед публикацией

```bash
python3 tools/check_content.py     # валидация JSON, путей к фото, ссылок меню
bash   tools/run_tests.sh          # смоук-тест: страница реально собирается (нужен jsdom)
```

Смоук-тест ставится один раз и только для разработки: `npm install --no-save jsdom`.

## 3. Как устроен контент

`data/site.json` состоит из трёх частей:

| Часть        | Зачем                                                                  |
|--------------|------------------------------------------------------------------------|
| `site`       | Название, телефон, адрес, соцсети, пункты меню, кнопка действия        |
| `settings`   | Цвета, скругления, ширина контейнера, число колонок — дизайн без CSS   |
| `blocks[]`   | Массив блоков страницы **сверху вниз**. Порядок в массиве = порядок на сайте |

Каждый блок — объект с полем `type`. Типов восемь: `hero`, `promo`, `text-image`,
`text`, `menu`, `gallery`, `team`, `contacts`. Главный «конструктор» — это
`text-image`:

```jsonc
{
  "id": "o-nas",
  "type": "text-image",
  "imagePosition": "left",        // "left" | "right" | убрать поле = текст по центру
  "title": "О ресторане",
  "text": "Первый абзац.\n\nВторой абзац.",
  "image": { "src": "assets/img/about.jpg", "alt": "Шеф за работой" },
  "features": ["Пункт 1", "Пункт 2"],
  "buttons": [{ "label": "Подробнее", "target": "komanda", "style": "ghost" }]
}
```

Полное описание каждого поля всех типов — в **`docs/JSON_SCHEMA.md`**.

### Повседневные задачи

| Хочу…                          | Делаю                                                                      |
|--------------------------------|----------------------------------------------------------------------------|
| Поменять цену                  | `blocks → menyu → categories → items → price`                              |
| Зачеркнуть старую цену         | Добавить `"oldPrice": 3200` рядом с `price`                                |
| Новая акция                    | Отредактировать блок `type: "promo"` (или добавить второй такой же)        |
| Скрыть блок, не удаляя         | `"visible": false`                                                         |
| Поменять блоки местами         | Переставить объекты внутри `blocks`                                        |
| Добавить раздел                | Скопировать блок, поменять `id`, `type`, содержимое                        |
| Поменять цвет акцента          | `settings.colors.accent`                                                   |
| Другой телефон/адрес           | `site.phone`, `site.address` — подставятся в шапку, контакты, подвал, SEO  |

## 4. Фотографии

1. Положите файлы в `assets/img/` под теми именами, что указаны в JSON
   (`hero.jpg`, `about.jpg`, `blyudo-1.jpg` …). Расширение в JSON менять не
   обязательно: если рядом с `photo.jpg` лежит `photo.webp`, браузер сам возьмёт
   лёгкий webp.
2. (Рекомендуется) прогоните сжатие — оно обрежет фото под нужный формат и
   сделает jpg + webp:

   ```bash
   # исходники кладём в assets/img/_original/ с именами из списка TARGETS
   python3 tools/optimize_images.py
   ```

   После этого исходники из `_original/` можно удалить (в git они не попадают).
3. Проверьте себя: `python3 tools/check_content.py` подскажет, если файла нет,
   если забыт `alt` или если картинка тяжелее 400 КБ.

Текущие фото в проекте — заглушки: 3 сгенерированных (hero, about, promo) и
SVG-плейсхолдеры с подписями, что куда положить.

## 5. Развёртывание (коротко)

Подробности и чек-листы — **`docs/DEPLOY.md`**.

| Способ            | Команда / действие                                                     | Когда выбирать                    |
|-------------------|------------------------------------------------------------------------|-----------------------------------|
| GitHub Pages      | push в `main` → workflow сам опубликует                                 | Бесплатно, контент правится в web |
| Netlify / Vercel  | подключить репозиторий (конфиги уже лежат)                              | Бесплатно, превью каждой правки   |
| Docker            | `docker build -t restaurant . && docker run -p 8080:80 restaurant`      | Сервер с Docker, единый образ     |
| VPS + nginx       | `sudo bash deploy/vps-install.sh ваш-домен.ру`                          | Полный контроль, свой домен       |

Во всех случаях на сервер уезжают только `index.html`, `assets/`, `data/`,
`robots.txt`, `sitemap.xml` — папка `tools/` остаётся у разработчика.

Обновление контента на бою = заменить `data/site.json` (и, если менялись фото,
файлы в `assets/img/`). Перезапускать ничего не нужно: JSON отдаётся с
заголовком «не кэшировать», правки видны сразу.

## 6. Как добавлять свои типы блоков (если понадобится)

1. В `assets/js/app.js` напишите функцию `renderMyblock(block)` по образцу
   существующих (она возвращает DOM-узел).
2. Зарегистрируйте её в таблице `RENDERERS`: `'myblock': renderMyblock`.
3. Добавьте стили в `assets/css/style.css` и описание в `docs/JSON_SCHEMA.md`.
4. В `tools/check_content.py` допишите тип в `KNOWN_TYPES`, чтобы проверка
   не ругалась.

Всё остальное (порядок, видимость, ссылки меню) работает для новых типов
автоматически.

## 7. Что уже продумано «на вырост»

- **SEO**: title/description/OG-карточка/schema.org (Restaurant) собираются из JSON;
  `robots.txt` и `sitemap.xml` готовы.
- **Доступность**: семантика (`header/main/section/footer`), `alt` у картинок,
  фокус-стили, `aria` у бургера, уважение `prefers-reduced-motion`.
- **Скорость**: webp + lazy-loading, сжатие gzip/brotli на уровне хостинга,
  кэш-заголовки для статики, нет внешних шрифтов и библиотек (0 запросов на CDN).
- **Печать**: меню печатается без шапки/галереи (`@media print`).
- **Защита от опечаток**: `check_content.py` ловит битый JSON, битые ссылки меню
  и отсутствующие файлы до публикации; CI на GitHub Pages прогоняет его сам.
