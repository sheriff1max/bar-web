# Сайт

Одностраничный адаптивный сайт (ПК / планшет / смартфон), собранный **без единой зависимости и без сборки**: чистые HTML + CSS + JS. Всё содержимое — тексты, цены, акции, фотографии, порядок блоков — лежит в одном файле **`data/site.json`** и меняется без правки HTML.

---

## 1. Локальный старт

```bash
cd bar-web

# вариант А (Node):
node serve.js                 # → http://localhost:8080

# вариант Б (Python, если Node не установлен):
python3 -m http.server 8080   # → http://localhost:8080
```

Откройте `http://localhost:8080`, отредактируйте `data/site.json`, нажмите F5 —
изменения на экране.

### Проверки перед публикацией

```bash
python3 tools/check_content.py     # валидация JSON, путей к фото, ссылок меню
bash   tools/run_tests.sh          # смоук-тест: страница реально собирается (нужен jsdom)
```

Смоук-тест ставится один раз и только для разработки: `npm install --no-save jsdom`.

## 2. Структура проекта

```

├── index.html              каркас страницы: шапка, подвал, <main> — без контента
├── data/

├── assets/
│   ├── css/style.css       стили и адаптив (тема дублируется в settings.colors JSON)
│   ├── js/app.js           движок: читает JSON и рисует блоки сверху вниз
│   └── img/                ваши фотографии + favicon.svg + og.jpg
│       └── _original/      (необязательно) исходники фото до сжатия

│   ├── optimize_images.py  сжатие фото в jpg+webp под нужные размеры
│   ├── make_sitemap.py     генерация sitemap.xml из site.url
│   ├── smoke_test.js       автотест сборки страницы (jsdom)
│   ├── screenshot.js       скриншоты на 3 разрешениях (playwright, опционально)
│   └── run_tests.sh        запуск смоук-теста вместе с локальным сервером

├── deploy/                 готовые файлы для VPS: nginx-конфиг и скрипт установки
```

Звёздочкой помечены файлы, с которыми вы будете работать чаще всего.

## 3. Фотографии

1. Положите файлы в `assets/img/` под теми именами, что указаны в JSON
   (`hero.jpg`, `about.jpg`, `blyudo-1.jpg` …). Расширение в JSON менять не
   обязательно: если рядом с `photo.jpg` лежит `photo.webp`, браузер сам возьмёт лёгкий webp.

2. (Рекомендуется) прогоните сжатие — оно обрежет фото под нужный формат и
   сделает jpg + webp:

   ```bash
   # исходники кладём в assets/img/_original/ с именами из списка TARGETS
   python3 tools/optimize_images.py
   ```

   После этого исходники из `_original/` можно удалить (в git они не попадают).

3. Проверьте себя: `python3 tools/check_content.py` подскажет, если файла нет,
   если забыт `alt` или если картинка тяжелее 400 КБ.

Текущие фото в проекте — заглушки: 3 сгенерированных (hero, about, promo) и
SVG-плейсхолдеры с подписями, что куда положить.

## 4. Как добавлять свои типы блоков (если понадобится)

1. В `assets/js/app.js` напишите функцию `renderMyblock(block)` по образцу
   существующих (она возвращает DOM-узел).
2. Зарегистрируйте её в таблице `RENDERERS`: `'myblock': renderMyblock`.
3. Добавьте стили в `assets/css/style.css` и описание в `docs/JSON_SCHEMA.md`.
4. В `tools/check_content.py` допишите тип в `KNOWN_TYPES`, чтобы проверка
   не ругалась.

Всё остальное (порядок, видимость, ссылки меню) работает для новых типов
автоматически.
